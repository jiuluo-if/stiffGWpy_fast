## Project mapping and candidate decision

The current Fast path uses a real 2×2 Cartesian state transfer (`scaled_step` / `solve_kernel`), explicit horizon-turn branches, and exact reheating-kink splitting. The background has mathematically distinct parameter branches (`cr=0` versus positive `cr`) and thermal-table/spline boundaries. The existing normalized post-reheating coordinate

` s = (N - N_re_abs) / N_re `

removes a redundant absolute offset from part of the post-event background representation, but the recorded full-Fast probe showed a shifted high-frequency cutoff and a `0.006073 dex` spectrum difference for two distinct `cr=0` models. It therefore does not establish spectrum or root invariance. Keep pre-event and post-event charts separate, preserve both one-sided event data and exact matching, and transform all derivatives, initialization/support, and outer-map quantities before using the chart in production.

No paper in this screen supplies a validated uniform error bound from background through mode transfer, frequency integral, `DN_gw` map, and self-consistent root. For a fixed point `x=G(x)`, a root residual alone is insufficient; a bound requires a verified contraction/slope enclosure (for example `|G'| <= q < 1`) or another root-isolation argument. The local quadrature indicators in current experiments are empirical and can understate the observed corner root error.

**Decision:** retain the priority architecture as event-aligned normalized background + current Fast transfer + a globally accountable frequency/root error estimator. Do not replace the propagation core on the basis of these papers. Continue only if a single mathematical mechanism improves a connected multi-dimensional valid region while meeting the existing `2e-4` root, `1e-3 dex` spectrum, and 5% warm P50/P95 regression gates. The current `log_natural_cubic`/`goal_auto` experiments remain opt-in: the recorded low-temperature corner root miss and regional speed misses preclude promotion.

## Minimum counterexample and verification set

1. Compare native-N and event-aligned evaluations at identical physical inputs/frequencies with the event both on a grid node and between nodes. Compare one-sided `sigma`, `H²`, `Phi`, `S²`, `f_hor`, transfer, spectrum, map, and root.
2. Move `N_re_abs` continuously through a fixed grid node; include event/start coincidences, post-event initialization, pre-event modes, and the `j0=0` clamp. Any algorithmic jump must be distinguished from the physical branch/event.
3. Cross the `cr=0`/positive-`cr` parameterization and thermal spline/analytic boundaries; certify separate charts or explicitly exclude degeneracies such as vanishing chart length.
4. For any new propagation variable, compare across a continuous sweep through the horizon turn, long evanescent growth, weak/strong dynamic range, and exact reheating matching. Monitor Wronskian/transfer residuals and final outputs.
5. Validate fixed-point roots on identical frequency arrays and background/tail conventions, followed by a nested frequency convergence check. Report frozen default Reference `z_tail=5` compatibility separately from deep-tail convergence.
6. Run the old trusted profiles and the candidate region with fixed resources, alternating paired warm P50/P95, memory and thread checks. Candidate selection must not rely on the same points used to tune it.

## Context7 API documentation check

Context7 was called for Numba and SciPy. The current [Numba threading documentation](https://numba.readthedocs.io/en/stable/user/threading-layer.html) states that `set_num_threads()` applies before parallel execution and can lower the runtime mask only up to the configured pool size; the [cache documentation](https://numba.readthedocs.io/en/stable/user/jit.html) notes file caching and global-constant/invalidation limitations. These are operational constraints for future A/B experiments, not numerical evidence. The [SciPy interpolation documentation](https://docs.scipy.org/doc/scipy/tutorial/interpolate/splines_and_polynomials.html) documents `PchipInterpolator.integrate()` and spline boundary behavior; natural boundary conditions specify zero second derivative at the endpoint, not globally linear extrapolation. This confirms API semantics only and does not validate the project's custom quadrature implementation.
